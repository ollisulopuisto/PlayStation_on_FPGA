## 2026-11-06 - Dispatch Parser Statements by Token Kind Rather than Linear Keyword Matching
**Learning:** In recursive descent AST parsers like `sflp_parse.py`, linear keyword checks (`if self.at('kw1'): ... elif self.at('kw2'): ...`) in hot methods like `action()` waste significant CPU cycles repeatedly checking keywords even though token kind (`name` for identifiers vs `kw` for statements vs `op` for blocks) already partitions the grammar. Unpacking sets into variadic helper arguments (`*self.DECL_KW`) also allocates tuples on every call.
**Action:** Always dispatch statement parsers by token kind first, and use dedicated set membership helpers (`at_decl()`) instead of unpacking collections into `at(*set)`.

## 2026-11-07 - Rejected: byte-lane mask loop in psx_mem_word_adapter.sv
**Learning:** The same 16-iteration byte-lane loop pattern (fixed in `psx_mem_fabric.sv` via PR #12) exists in `psx_mem_word_adapter.sv`. Replacing it with bitmask ops (`req_mask & ((1 << (2*len)) - 1)` and `(1 << (2*len*8)) - 1`) is functionally equivalent but NOT measurable: `tb_psx_mem` simulation time is dominated by testbench scoreboard/traffic overhead, not the DUT's combinational mask computation. Interleaved paired runs (10 pairs, +cycles=5000): baseline avg 3.052s vs optimized avg 2.950s, but paired t-test t ≈ -0.5 (p > 0.5) — within run-to-run noise. Some paired runs showed optimized slower.
**Action:** Do not re-attempt combinational mask optimizations in RTL that is only a small fraction of testbench simulation time. Before investing in an HDL optimization, verify the target is a measurable fraction of simulation time with a quick baseline.
